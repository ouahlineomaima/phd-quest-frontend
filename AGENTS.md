# Repository workflow

After each completed and validated semantic unit, review changes, run relevant checks, stage only related files, create a descriptive Conventional Commit, locally. Push to origin/main (or the explicitly requested working branch) only if GitHub authentication is already working; pushes are optional. If authentication is unavailable, continue development without repeated authentication attempts or requests for credentials. Report every local commit hash and any push result. Keep frontend and backend commits separate. Never commit secrets, databases, backups, dependencies, build outputs or temporary files. Do not force-push, rewrite remote history, or amend pushed commits without explicit authorization. If a push fails, retain the local commit and report the failure. Fix failing checks before committing. Stop at the requested phase.
